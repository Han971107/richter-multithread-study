섹션 1: 중단·재개·컨텍스트 전환

Windows 스케줄러 기본

Windows는 선점형(preemptive) 우선순위 기반 스케줄러. 매 퀀텀(quantum)(≈15~30ms)마다 다음 실행할 스레드 교체 결정. 현재 스레드를 강제로 멈출 수 있음.

SuspendThread / ResumeThread

DWORD SuspendThread(HANDLE hThread);   // 리턴: 이전 suspend count
DWORD ResumeThread(HANDLE hThread);    // 리턴: 이전 suspend count
  • 각 스레드는 내부 suspend count를 가짐. SuspendThread → +1, ResumeThread → -1
  • count가 0이 되어야 실행 재개
  • CreateThread(..., CREATE_SUSPENDED) → count=1로 생성 → 준비 완료 후 ResumeThread
위험: 대상 스레드가 힙 할당·뮤텍스 보유 중에 suspend되면 데드락. 외부 스레드 suspend는 디버거 용도 외엔 쓰지 말 것.

Sleep / SwitchToThread / YieldProcessor 비교

VOID Sleep(DWORD dwMilliseconds);
BOOL SwitchToThread(VOID);
YieldProcessor(); // 인트린식 (x86: PAUSE, ARM: YIELD)
함수OS 개입양보 대상용도
YieldProcessor없음없음 (CPU 힌트만)스핀루프 내부
Sleep(0)있음동일 우선순위 이상협력적 양보
SwitchToThread있음낮은 우선순위 포함starvation 방지 스핀락
Sleep(0) vs SwitchToThread(): SwitchToThread는 낮은 우선순위 스레드에게도 양보 가능.

GetThreadTimes

BOOL GetThreadTimes(HANDLE hThread,
    PFILETIME pCreationTime, PFILETIME pExitTime,
    PFILETIME pKernelTime,   PFILETIME pUserTime);

커널 모드 vs 유저 모드 소비 시간 분리. 게임 물리 스레드가 과도하게 시스템 콜 치는지 진단 시 사용.

섹션 2: 우선순위 시스템

두 층짜리 추상화

  1. 프로세스 우선순위 클래스 (6가지) — 프로세스 단위
  2. 스레드 우선순위 레벨 (7가지) — 클래스 내 상대적 위치

이 둘의 조합 → 실제 우선순위(0~31)로 변환

프로세스 우선순위 클래스

SetPriorityClass(GetCurrentProcess(), 클래스_상수);
상수의미
IDLE_PRIORITY_CLASS시스템이 놀 때만 (스크린세이버류)
BELOW_NORMAL_PRIORITY_CLASSNormal보다 약간 낮음
NORMAL_PRIORITY_CLASS기본값 (대부분 앱)
ABOVE_NORMAL_PRIORITY_CLASSNormal보다 약간 높음
HIGH_PRIORITY_CLASS시간 임계 작업용
REALTIME_PRIORITY_CLASS⚠️ OS 스레드까지 선점. 관리자 권한 필요
REALTIME_PRIORITY_CLASS 금지: 마우스·키보드·디스크 I/O 처리하는 OS 스레드도 선점 → 시스템 멈춤.

스레드 우선순위 레벨

SetThreadPriority(GetCurrentThread(), 레벨_상수);
상수의미
THREAD_PRIORITY_IDLE고정 1 (REALTIME에선 16)
THREAD_PRIORITY_LOWEST클래스 기준 -2
THREAD_PRIORITY_BELOW_NORMAL-1
THREAD_PRIORITY_NORMAL기본 (0)
THREAD_PRIORITY_ABOVE_NORMAL+1
THREAD_PRIORITY_HIGHEST+2
THREAD_PRIORITY_TIME_CRITICAL고정 15 (REALTIME에선 31)

실제 우선순위 매핑 테이블

레벨 0 = Zero Page Thread 전용 (사용 불가). 레벨 16~31 = REALTIME_PRIORITY_CLASS만 접근 가능.

게임 엔진 활용 패턴

SetThreadPriority(hRenderThread,      THREAD_PRIORITY_ABOVE_NORMAL);
SetThreadPriority(hAudioThread,       THREAD_PRIORITY_HIGHEST);
SetThreadPriority(hAssetLoaderThread, THREAD_PRIORITY_BELOW_NORMAL);
Unreal Engine의 EThreadPriority enum은 내부적으로 이 Win32 상수로 변환됨.

섹션 3: 동적 우선순위 부스팅 & 퀀텀 구조

동적 우선순위 부스팅(Dynamic Priority Boost)

특정 이벤트 시 스레드 우선순위를 일시적으로 올려줌. 부스트된 우선순위는 퀀텀이 끝날 때마다 1씩 내려가 원래 값으로 복귀.

트리거설명
I/O 완료디스크/네트워크 대기 중이던 스레드가 깨어날 때 (+1~+2)
윈도우 메시지 수신포어그라운드 GUI 이벤트 처리 스레드
동기화 객체 해제세마포어/뮤텍스 신호 받아 대기 해제된 스레드

포어그라운드 프로세스 퀀텀 부스팅

활성 창(포어그라운드) 프로세스 스레드의 퀀텀이 최대 3배 더 길어짐. 백그라운드 서버 프로세스는 이 혜택 없음.

SetThreadPriorityBoost — 동적 부스팅 비활성화

BOOL SetThreadPriorityBoost(HANDLE hThread, BOOL bDisablePriorityBoost);
BOOL GetThreadPriorityBoost(HANDLE hThread, PBOOL pbDisablePriorityBoost);
게임의 렌더·물리 스레드처럼 퀀텀을 일정하게 유지해야 할 때 부스팅을 끄면 스케줄링 예측성이 올라감.

퀀텀(Quantum) 구조

높은 우선순위 스레드 등장  → 즉시 선점 (퀀텀 남아도 뺏김)
동일 우선순위끼리          → 라운드 로빈 (퀀텀 소진 후 다음)
낮은 우선순위 스레드       → 높은 우선순위 스레드가 전부 대기일 때만 실행
기아(Starvation): 높은 우선순위 스레드가 절대 잠들지 않으면 낮은 우선순위 스레드는 영원히 실행 안 됨. 동적 부스팅이 완화하지만 설계 수준에서 고려 필요.

섹션 4: CPU 친화성 (Affinity)

왜 친화성이 필요한가

스레드가 코어를 옮기면 발생하는 문제:

  • 캐시 미스: 코어를 옮기면 L1/L2 캐시를 다시 채워야 함
  • NUMA 패널티: NUMA 시스템에서 다른 노드의 메모리 접근 시 지연 발생
  • 타이밍 예측 불가: 코어가 바뀌면 실행 시간 예측이 어려워짐

Soft Affinity vs Hard Affinity

종류설명API
Soft Affinity"가능하면 이 코어 선호" 힌트. 보장 없음SetThreadIdealProcessor
Hard Affinity이 코어 집합에서만 실행. 강제 제한SetThreadAffinityMask

SetProcessAffinityMask

BOOL SetProcessAffinityMask(HANDLE hProcess, DWORD_PTR dwProcessAffinityMask);
BOOL GetProcessAffinityMask(HANDLE hProcess,
    PDWORD_PTR pdwProcessAffinityMask,  // 프로세스 친화성 마스크
    PDWORD_PTR pdwSystemAffinityMask);  // 시스템 전체 코어 마스크

마스크는 비트맵: 4코어에서 코어 0,1만 허용 → mask = 0b0011. 프로세스 내 모든 스레드에 적용.

SetThreadAffinityMask

DWORD_PTR SetThreadAffinityMask(HANDLE hThread, DWORD_PTR dwThreadAffinityMask);

스레드 개별 친화성. 프로세스 마스크의 부분집합이어야 함. 리턴값 = 이전 마스크.

// 렌더 스레드를 코어 0에 고정
SetThreadAffinityMask(hRenderThread, 1 << 0);

// 물리 스레드를 코어 2,3에 고정
SetThreadAffinityMask(hPhysicsThread, (1 << 2) | (1 << 3));

SetThreadIdealProcessor — 소프트 힌트

DWORD SetThreadIdealProcessor(HANDLE hThread, DWORD dwIdealProcessor);

하드 친화성의 과도한 제약 없이 캐시 효율을 높일 때 사용. OS가 최대한 지켜주지만 보장 없음.

GetLogicalProcessorInformation

BOOL GetLogicalProcessorInformation(
    PSYSTEM_LOGICAL_PROCESSOR_INFORMATION pBuffer,
    PDWORD pdwReturnLength);

물리 코어 수, 논리 코어 수(하이퍼스레딩 포함), L캐시 공유 관계 등 코어 토폴로지 정보. 게임 엔진 초기화 시 스레드 풀 크기와 친화성 전략 결정에 사용.

실전 패턴: 게임 엔진 스레드 레이아웃

코어 0: 메인 스레드 (게임 로직)
코어 1: 렌더 스레드 (드로콜 생성)
코어 2: 오디오 스레드
코어 3: 물리 스레드
코어 4,5: 워커 스레드 풀 (Job System)
과도한 친화성 고정 주의: 코어 0이 바쁠 때 코어 1이 놀아도 메인 스레드를 도울 수 없게 됨. Job System(Ch 13)에서 친화성을 동적으로 관리하는 이유.
